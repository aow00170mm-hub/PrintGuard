# PrintGuard 自動設備設定檔計畫

## 目的

PrintGuard 新增、更換或重新命名印表機時，應自行偵測並開始收集列印資料。不得為每一個佇列名稱在程式碼中建立專屬判定，也不得因換機或換驅動就要求重新編譯程式。

## 核心原則

1. Agent 自動發現 Windows Print Server 可見的所有佇列。
2. 設備判定規則存放於 SQLite，不寫死 `PRINT_401` 等佇列名稱。
3. 設定檔以驅動名稱、驅動版本、設備能力及其他穩定資訊建立指紋。
4. 相同指紋的新佇列可沿用已驗證的設定檔。
5. 指紋改變時自動重新偵測，不盲目沿用舊設備規則。
6. 硬體只能黑白或只能單面時，可由設備能力直接判定。
7. 彩色／雙面設備只有在工作欄位可信時才依 DEVMODE 判定。
8. 資料矛盾或不足時保留「待確認」，不得猜測並造成錯誤計費。
9. 管理員可在網頁覆寫設備能力與信任方式；設定存資料庫，不需改程式碼。
10. 列印限制政策與報表判定設定分離：政策決定允許什麼，設備設定檔決定如何解讀工作。

## 自動判定順序

1. 讀取佇列及驅動提供的設備能力。
2. 建立或尋找相同設備指紋的設定檔。
3. 若設備明確不支援彩色，工作判定為黑白。
4. 若設備明確不支援雙面，工作判定為單面。
5. 若設定檔已驗證標準 DEVMODE 欄位可信，採用工作值。
6. 若設定檔有已驗證的私有 DEVMODE 規則，採用該規則。
7. 其餘維持未知並顯示於待確認清單。

## 設定檔狀態

- `auto`：系統自動建立，尚未人工驗證。
- `verified`：能力或欄位規則已經測試確認。
- `needs_review`：資料缺少或互相矛盾。

## 管理員可設定項目

- 彩色能力：自動／僅黑白／支援彩色。
- 雙面能力：自動／僅單面／支援雙面。
- 彩色工作欄位：保守／信任標準 DEVMODE。
- 雙面工作欄位：保守／信任標準 DEVMODE。
- 設定是否已驗證。

## 第一階段實作範圍

- SQLite 設備設定檔與佇列關聯。
- Agent 同步驅動與可取得的設備能力。
- 後端依指紋自動建立或沿用設定檔。
- Agent 取得設定檔並依上述優先順序判定工作。
- 網頁顯示設定檔狀態並提供覆寫介面。
- 未知資料繼續保留，不影響總工作數與總頁數。

## 後續階段

- 讀取驅動版本與更完整的 DeviceCapabilities。
- 驅動私有 DEVMODE 規則校準工具。
- EMF／PCL／PostScript 工作內容解析。
- SNMP 設備計數器對帳。
- 真正 Windows Service 封裝。

## 驗收條件

1. 新增佇列後不修改程式即可在網頁出現並開始收集。
2. 相同設備指紋可自動沿用設定檔。
3. 更換驅動或設備指紋後會重新偵測。
4. 黑白硬體不會因驅動回傳 `dmColor=2` 被誤算彩色。
5. 未驗證的彩色／雙面欄位不會被猜測。
6. 管理員覆寫後不需重新啟動或重新編譯即可生效。
7. 政策阻擋、成功報表及30天 Log 保留機制維持正常。
